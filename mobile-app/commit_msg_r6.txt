fix(mobile-app): R6 regression audit — abort race, phantom re-render, grid layout, listener leak

Reviewed commits R1-R5 for bugs introduced by the optimization refactors.

#33 (HIGH) RequestGuard never aborted the previous in-flight request:
  R2 added AbortController per run() but never called .abort() on the previous
  controller — the generation counter only prevented stale state writes, not
  wasted network calls. Now holds currentController ref and aborts it when a
  new request starts; finally block clears the ref.

#34 (HIGH) DashboardScreen subscribed to health state but never used it:
  R2 removed the dead status variable but left the useStore health selector,
  so every 10s health poll triggered a pointless DashboardScreen re-render.
  Removed the selector; only fetchHealth (stable fn) is subscribed now.

#35 (MEDIUM) ProvidersScreen numColumns=2 + ItemSeparatorComponent:
  R3 kept the separator after switching to a 2-column grid, but FlashList
  inserts separators between horizontal neighbors too, causing uneven gutters.
  Removed separator; card spacing now handled by margin + flex in ProviderCard.

#36 (LOW) mergeSignals event-listener leak:
  R4 attached an abort listener to the external signal but cleanup only
  cleared the timeout. Now removes the listener in cleanup to prevent leaks
  over repeated poll cycles.

Wiki: updated mobile-app-performance.md (sections 33-36) and log.md.
Validation: npx tsc --noEmit passes clean.
