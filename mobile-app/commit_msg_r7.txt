fix(mobile-app): R7 second bug audit — dead props, format inconsistency, parse errors, wasted polls

Second-pass review after R6, focusing on dead code, UI consistency, and robustness.

#37 (MEDIUM) ModelRankRow dead maxRequests prop:
  Component accepted maxRequests but never rendered it. DashboardScreen ran a
  useMemo to compute it, triggering extra re-renders. Removed prop + memo.

#38 (MEDIUM) ProviderCard raw number rendering:
  Rendered item.requests as raw number instead of formatNumber(), inconsistent
  with all other cards. Large numbers overflowed the narrow grid card.
  Now uses formatNumber for consistency.

#39 (LOW) fetchJSON uncaught JSON parse failure:
  If server returned 200 OK with non-JSON body (e.g. reverse proxy HTML error),
  res.json() threw raw SyntaxError, uncaught by network catch block, surfaced
  as misleading NETWORK error. Now caught and thrown as ApiError SERVER.

#40 (MEDIUM) RequestGuard dead AbortError check:
  fetchJSON already wraps all AbortErrors into ApiError TIMEOUT, so the
  RequestGuard AbortError check was unreachable dead code. Removed it;
  superseded requests are now handled implicitly via gen !== this.generation.

#41 (MEDIUM) DashboardScreen wasted health polling:
  After R6 removed health state subscription, fetchHealth was still called every
  10s but health data was never consumed by any UI. Removed from polling.

Wiki: updated mobile-app-performance.md (sections 37-41) and log.md.
Validation: npx tsc --noEmit passes clean.
